# 一、Google workspace 文件與多模態向量庫同步

將 Google Workspace 中指定範圍的文件，完整同步至 Qdrant 多模態向量庫，以支持 Agent 的文件多模態相似度搜尋。

## 1. Google Workspace 文件同步

系統需維持指定的 Google Workspace 文件來源中的文件狀態與向量庫資料的一致性，包含文件新增、修改、移動、重新命名與刪除。

背景同步以 Service Account 憑證搭配 Domain-Wide Delegation 存取 Google Workspace。

同步採全量清單比對：先分別取得 Google Workspace 掃描範圍內的完整文件清單，以及 Qdrant 向量庫中已同步文件的完整清單（以 Google file ID 為單位彙總），再交叉比對以判斷文件變動。

比對結果依下列方式處理：

```text
1. 僅存在於 Google Workspace：執行完整匯入流程
2. 僅存在於向量庫：移除該文件在向量庫中的全部資料
3. 兩邊皆存在但判定有變動(用 Google Drive 檔案 version 比對是否變動)：先移除該文件在向量庫中的全部資料，再重新執行完整匯入流程
4. 兩邊皆存在且判定無變動：略過
```

有變動的文件一律以整份文件為單位處理：刪除該文件在向量庫中的既有資料後，重新產生向量並寫入，避免殘留過期頁面或部分更新不一致。文件刪除或自掃描範圍移除時，亦需同步清除向量庫中對應資料，避免搜尋結果指向不存在或過期的內容。

## 2. 文件分頁向量化

系統在執行每份文件向量化時，依下列步驟進行：

```text
1. 將文件轉成每頁一張圖片
2. 將每頁圖片以阿里雲多模態 Embedding 模型向量化
3. 將每頁的向量與必要 metadata 匯入 Qdrant 向量庫

```

支援的文件類型包括 PDF、Word、PowerPoint、TXT、MD、Google Docs、Google Slides、PNG、JPG、JPEG、WEBP。

PNG、JPG、JPEG、WEBP 視為單頁文件，頁碼固定為 1，先整理為單頁 PNG 後再進行向量化；其他類型文件都先轉成 PDF 後再依頁轉圖。

Excel 與 Google Sheets 因內容格式不固定，不納入支援文件類型。使用者需手動轉成以 A4 版面呈現的 PDF，確認格式正確後再放入掃描範圍。

## 3. 每頁向量 metadata

匯入 Qdrant 向量庫時，每頁向量需附帶必要 metadata，至少需能回溯：

```text
1. Google file ID
2. 原始文件名稱
3. 原始文件路徑或位置
4. 原始文件連結
5. Google Drive 檔案 version（§1 同步比對依據）
6. Google Drive 最後修改時間（modifiedTime）
7. 頁碼
```

# 二、使用者查詢與 Codex Agent 閱讀

讓使用者透過 Codex Agent 以自然語言或圖片進行查詢，並讓 Agent 取得使用者有權限存取的相關文件頁面與原始文件。

## 1. 全文關鍵字搜尋與多模態相似度搜尋

使用者可向 Codex Agent 提出自然語言問題，或上傳圖片作為查詢依據。收到查詢後，系統並行執行下列兩類搜尋，取得兩者的查詢結果清單：

**Google Workspace 全文關鍵字搜尋**

Agent 從使用者提出的問題與圖片(若有的話)中抽取關鍵字後，以**目前使用者**的 OAuth 憑證呼叫 Google Drive API，利用檔名、全文或 metadata 搜尋能力進行查詢。

其回傳結果為**檔案層級**（`file_id`、檔名等），**不含文件內頁碼**；並依 Google API 原始相關性排序。

此路徑適合處理明確、可逐字比對的詞彙，例如客戶名稱、專案代碼、產品型號、合約編號、人名、日期、文件名稱，用來補強向量搜尋容易漏掉的編號與專有名詞。


**Qdrant 向量庫多模態相似度搜尋**

Agent 從使用者提出的問題與圖片(若有的話)中抽取關鍵字，將關鍵字與圖片(若有的話)透過阿里雲多模態 Embedding 模型轉為查詢向量，並依 Agent 指定的回傳筆數或最低相似度分數閾值，至向量庫進行分頁向量的相似度搜尋。

將**頁面層級**的搜尋結果以 Google file ID 彙總為兩層結構：上層為檔案，下層為該檔案命中的頁面清單。上層檔案依該檔內最高相似度分數由高到低排序；同一檔案內各頁依相似度分數由高到低排序。

接下來，逐檔案以目前使用者的 OAuth 憑證向 Google Drive API 確認是否仍可存取，並剔除掉無權限存取的檔案。

此路徑適合語意相近、圖片相似、或使用者難以用文字精確描述需求的情境。


## 2. 任務工作資料夾

Agent 收到新的使用者任務時，須建立一個獨立任務工作區。同一任務中的使用者輸入、後續查詢、分析內容與產出均集中於該任務工作區；若使用者提出的是既有任務的後續需求，應繼續使用原任務工作區。

任務中的一到多個查詢結果皆須放在固定位置，其餘內容由 Agent 依實際工作需求安排。

## 3. 查詢結果檔案下載

每次查詢均須於目前任務工作區中建立獨立的查詢結果資料夾，不得覆蓋或混用其他查詢的結果。若預定的查詢結果位置已存在，須在實際查詢前停止執行，避免既有內容遭到變更。

本次查詢結果資料夾建立成功後，依下列步驟整理內容：

```text
1. 建立本次實際查詢條件、全文搜尋結果與相似度搜尋結果清單
2. 取兩份結果清單的檔案聯集；聯集內的每份檔案各建立一個以安全檔名與 Google file ID 命名的資料夾
3. 將該檔案自 Google Workspace 下載的原始檔放入對應資料夾
4. 依頁碼將文件轉為 PNG，自 0001 起編號存放於同一資料夾（例如 0001.png、0002.png）
```

## 4. Codex Agent 閱讀與回覆原則

Codex Agent 不直接連線整個 Google Workspace 文件庫，僅依目前任務中的各次查詢結果資料夾、結果清單與已下載檔案進行閱讀與回覆，並遵循下列原則：

```text
1. 分析兩份查詢結果清單後，依最小閱讀原則自行判斷先讀哪些內容以回覆使用者問題：
   - 向量相似度命中：清單已標示頁碼，直接讀取對應單頁 PNG（例如 0003.png）
   - 全文關鍵字命中：Google 僅回傳檔案、不含頁碼；須先依本次查詢關鍵字在已下載原始檔中定位命中頁，再讀取該頁 PNG，不以整份原始檔或任意頁面代替
   - 同一檔案同時出現在兩份清單：優先參考向量清單中的頁面，並以原始檔關鍵字比對確認或補足其他命中頁
2. 回答時須附上單頁圖片連結與原始完整檔連結，並明確標示引用來源（全文或向量、檔案與頁碼）
3. 若判斷查詢結果內容品質不佳，可自動進行下一輪查詢，例如擴大回傳筆數、調整查詢語句或關鍵字等，再依本節原則閱讀與回覆
```
