# 一、Google Drive 文件與多模態向量庫同步

將 Google Drive 中指定範圍的文件，完整同步至 Qdrant 多模態向量庫，以支持 Agent 的文件多模態相似度搜尋。

## 1. Google Drive 文件同步

系統維持指定的 Google Drive 文件來源中的文件狀態與向量庫資料的一致性，包含文件新增、修改、移動、重新命名與刪除。

背景同步以 Service Account 憑證搭配 Domain-Wide Delegation 存取 Google Drive。

同步採全量清單比對：先分別取得 Google Drive 掃描範圍內的完整文件清單，以及 Qdrant 向量庫中已同步文件的完整清單（以 Google file ID 為單位彙總），再交叉比對以判斷文件變動。

比對結果依下列方式處理：

```text
1. 僅存在於 Google Drive：執行完整匯入流程
2. 僅存在於向量庫：移除該文件在向量庫中的全部資料
3. 兩邊皆存在但判定有變動（用 Google Drive 檔案 modifiedTime 比對是否變動）：先移除該文件在向量庫中的全部資料，再重新執行完整匯入流程
4. 兩邊皆存在且判定無變動：略過
```

有變動的文件一律以整份文件為單位處理：刪除該文件在向量庫中的既有資料後，重新產生向量並寫入，避免殘留過期頁面或部分更新不一致。文件刪除或自掃描範圍移除時，亦需同步清除向量庫中對應資料，避免搜尋結果指向不存在或過期的內容。

## 2. 文件分頁向量化

系統在執行每份文件向量化時，依下列步驟進行：

```text
1. 將文件轉成每頁一張圖片
2. 將每頁圖片以阿里雲多模態 Embedding 模型向量化
3. 將每頁的向量與必要 metadata 匯入 Qdrant 向量庫

```

支援向量化的文件類型包括 PDF、Word、PowerPoint、TXT、MD、Google Docs、Google Slides、PNG、JPG、JPEG、WEBP。

PNG、JPG、JPEG、WEBP 視為單頁文件，頁碼固定為 1，先整理為單頁 PNG 後再進行向量化；其他類型文件都先轉成 PDF 後再依頁轉圖。

Excel 與 Google Sheets 因內容格式不固定，不納入向量化支援類型。若需讓其內容進入向量庫，使用者需手動轉成以 A4 版面呈現的 PDF，確認格式正確後再放入掃描範圍。

## 3. 每頁向量 metadata

匯入 Qdrant 向量庫時，每頁向量需附帶必要 metadata，至少需能回溯：

```text
1. Google file ID
2. 原始文件名稱
3. 原始文件路徑或位置
4. 原始文件連結
5. Google Drive 檔案 version（供排錯與追蹤）
6. Google Drive 最後修改時間（modifiedTime，§1 同步比對依據）
7. 頁碼
```

# 二、使用者查詢與 Codex Agent 閱讀

讓使用者透過 Codex Agent 以自然語言或圖片進行查詢，並讓 Agent 取得使用者有權限存取的相關文件頁面與原始文件。

## 1. 關鍵字搜尋與多模態相似度搜尋

使用者可以向 Codex Agent 提出自然語言問題，或上傳圖片作為查詢依據。當收到查詢請求後，系統會引導使用者選擇要同時執行以下兩種搜尋，或只進行其中一種，並將每項搜尋的結果分別儲存在對應的查詢結果清單內：

**Google Drive 關鍵字搜尋**

Agent 從使用者提出的問題與圖片(若有的話)中抽取關鍵字後，以**目前使用者**的 OAuth 憑證呼叫 Google Drive API，利用檔名、全文或 metadata 的關鍵字搜尋能力進行查詢。

其回傳結果為**檔案層級**（`file_id`、檔名等），**不含文件內頁碼**；並保留 Google API 原始回傳順序。

此搜尋結果清單需至少包含檔案名稱、Google Drive file id 與 Google Drive 檔案連結。

注意：
- 搜尋範圍依目前使用者的 Google Drive 存取權限決定，不受同步到向量庫的來源資料夾範圍限制。
- 搜尋範圍不受本專案向量化支援類型限制；任何 Google Drive 上可儲存且支持關鍵字搜尋能力的 MIME type 檔案格式都包含在搜尋範圍內。如非文件格式的 ZIP 檔、影片檔等，也可能因檔名或 metadata 而命中。
- 搜尋結果清單會排除不可下載項目與不支持的 Google native MIME type (目前只支持 Google Docs / Slides / Sheets)。

此路徑適合處理明確、可逐字比對的詞彙，例如客戶名稱、專案代碼、產品型號、合約編號、人名、日期、文件名稱，用來補強向量搜尋容易漏掉的編號與專有名詞。

**Qdrant 向量庫多模態相似度搜尋**

Agent 將使用者原始描述或經使用者確認的查詢文字，連同圖片 (若有) 送至多模態 Embedding 模型轉為查詢向量，並依 Agent 指定的回傳筆數或最低相似度分數閾值，至向量庫進行分頁向量的相似度搜尋。

將**頁面層級**的搜尋結果以 Google file ID 彙總為兩層結構：上層為檔案，下層為該檔案命中的頁面清單。上層檔案依該檔內最高相似度分數由高到低排序；同一檔案內各頁依相似度分數由高到低排序。

接下來，逐檔案以目前使用者的 OAuth 憑證向 Google Drive API 確認是否仍可存取，並剔除掉無權限存取的檔案。

此搜尋結果清單需至少包含檔案名稱、Google Drive file id、Google Drive 檔案連結，以及各頁的頁碼與其相似度分數。

此路徑適合語意相近、圖片相似、或使用者難以用文字精確描述需求的情境。


## 2. 任務工作資料夾

Agent 收到新的使用者任務時，須建立一個獨立任務工作區。同一任務中的使用者輸入、後續查詢、分析內容與產出均集中於該任務工作區；若使用者提出的是既有任務的後續需求，應繼續使用原任務工作區。

任務中的一到多個查詢結果皆須放在固定位置，其餘內容由 Agent 依實際工作需求安排。

## 3. 查詢結果檔案下載

每次查詢均須於目前任務工作區中建立獨立的查詢結果資料夾，不得覆蓋或混用其他查詢的結果。若預定的查詢結果位置已存在，須在實際查詢前停止執行，避免既有內容遭到變更。

本次查詢結果資料夾建立成功後，依下列步驟整理內容：

```text
1. 建立本次實際查詢條件、關鍵字搜尋結果與相似度搜尋結果清單
2. 取本次實際執行之各搜尋結果清單的檔案聯集；若只執行一類搜尋，聯集即為該搜尋結果清單。
3. 針對聯集內的每份檔案各建立一個以安全檔名與 Google file ID 命名的資料夾。
4. 將檔案下載至對應資料夾；Google Docs 與 Google Slides 匯出為 PDF，Google Sheets 匯出為 XLSX，其餘檔案格式則下載原始格式。
5. 針對能轉換成 PDF 與逐頁文字內容的檔案格式，提供轉出的 PDF 版本與逐頁文字內容 (包括 PDF、Word、PowerPoint、TXT、MD、Google Docs、Google Slides)。
6. 針對能轉出單頁圖片的檔案格式，提供所有命中頁面的單頁圖片。相似度搜尋直接從搜尋結果取得命中頁面頁碼，而關鍵字搜尋則會用搜尋時使用的關鍵字從逐頁文字內容定位命中頁面頁碼。若同時執行兩類搜尋，且命中同一頁，不會重複產生。
```

注意：
- Google Drive 的關鍵字搜尋，會搜尋名稱、描述、indexableText、內容及部分 metadata，所以以上使用關鍵字從文件內容定位命中頁面的方式不一定找得到命中頁面。但若有命中頁面，則會將頁碼資訊與此頁命中的關鍵字資訊回寫到搜尋結果清單中。
- 圖片檔 (包括 PNG、JPG、JPEG、WEBP ) 只在相似度搜尋命中時以第 1 頁產生單頁圖片；Google Drive OCR 或全文搜尋命中圖片時，因無逐頁文字可供定位，維持檔案層級結果。
- 若個別檔案無法下載，或支援文件處理的檔案無法完成後續處理，不應中止其他檔案；系統須繼續處理剩餘檔案，保留已成功取得的結果，並提供失敗檔案、失敗階段、原因與原始文件連結。此外，若是相似度搜尋須另提供命中頁碼；若是關鍵字搜尋則須另提供本次查詢條件，讓 Agent 能向使用者說明本次查詢結果不完整，並協助使用者自行查看原始文件。

## 4. Codex Agent 閱讀與回覆原則

Codex Agent 不直接連線整個 Google Drive 文件庫，僅依目前任務中的各次查詢結果資料夾、結果清單與已下載檔案進行閱讀與回覆，並遵循下列原則：

```text
1. 完成搜尋後原則上不先解析各單頁圖片內容，而是引導使用者查看搜尋結果清單與各單頁圖片。並在使用者查看了搜尋結果後，用最高效的方式協助使用者完成後續詳細內容解析。
2. 解析哪些檔案、哪些頁面、深入到什麼程度，以呈現結果後與使用者討論的共識為準，並盡可能優先利用查詢結果清單、已轉出的單頁圖片(圖片內容理解)與逐頁文字內容(關鍵字搜尋)來優化解析效率，盡量避免讀取大檔之完整檔案內容。
3. 所有的內容解析都優先透過解析單頁圖片內容的方式進行，以確保同時讀到頁面中的文字、圖片與表格。因此若要解析的內容，是支援文件處理的檔案格式，但不在已轉出的單頁圖片範圍內，則需定位到要解析內容的頁碼後，再轉成單頁圖片進行解析。
4. 若是不支援文件處理的檔案格式(無法轉成單頁圖片進行解析)，則依 Agent 自身工具能力讀取與分析。
5. 回答時須註記引用的檔案頁面資訊(若有單頁圖片檔案，強制必須呈現此圖片在回答內容中)。
6. 若判斷查詢結果內容品質不佳，需與使用者確認調整後的查詢計畫，再進行下一輪查詢，例如擴大回傳筆數、調整查詢類別、查詢語句或關鍵字等，再依本節原則閱讀與回覆
```
